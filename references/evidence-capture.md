# 증거 캡처 — 스크린샷·조작 증거를 에이전트가 직접 확보하는 절차 (`adr/0021`, `adr/0014`)

**원칙**: 증거 매트릭스(어떤 뷰포트·모드·플랫폼을 찍나)는 절차가 아니라 **프로젝트 선언**(`.claude/cgamja.json` `evidence.*` + `platform.profile`)이 정한다. 촬영 수단이 선언돼 있지 않아도(=null) 사용자에게 먼저 묻지 않는다 — 아래 §1 순서로 직접 확보를 시도하고, 성공한 수단을 선언에 기록하고, 전부 실패했을 때만 요청한다. §4는 검증된 구현(스택·날짜 라벨)이다.

## 1. 촬영 수단 탐색 순서 (세션당 1회)
1. **선언**: `evidence.screenshot`이 명령/도구 이름이면 그것만 쓴다. 끝.
2. **프로젝트 기존 수단**: `scripts/`·`package.json` scripts·E2E 러너의 스크린샷 기능 — 이미 있는 걸 재사용한다(즉석 발명 금지의 첫 번째 이유).
3. **플랫폼 표준 도구**: 프로필에 맞는 §4의 검증된 구현. §4에 해당 스택이 없으면 조사 → 1회 실측 → **§4에 날짜와 함께 추가**한 뒤 쓴다(`feedback-install-and-verify`). **§4에 실측 레시피가 없는 플랫폼은 세션 중 즉석으로 뚫지 않는다** — "검증된 플랫폼 + 단위 테스트로 대체, 나머지는 선언된 한계"를 조기 판정하고 PR에 적는다(adr/0025 — Android 개척에 18분 소모 후 미완 실측). 개척은 티켓 작업이 아니라 별도 세팅 작업으로.
4. **사용자 요청**: 위가 전부 안 될 때만. 무엇을 몇 장, 어떤 상태로 찍어야 하는지 목록으로 요청하고 경로를 받는다.

성공한 수단은 `evidence.screenshot`에 기록을 제안한다(선언 파일은 보호 대상 — Edit 승인 경로로). 다음 세션은 탐색을 건너뛴다.

**운전은 스크립트로, 판정만 모델로(adr/0025).** 비용 실측상 증거 국면의 지출은 이미지가 아니라 인터랙티브 운전(좌표 추측·재조정·재시도)이다 — 세션당 증거 비용 ≈$11~14, 그중 이미지 바이트는 장당 몇 센트. 증거 대상 화면마다 "상태 주입(경계 mock 모드) → 딥링크 route → 캡처"를 프로젝트 스크립트(예: `scripts/evidence/<화면>.sh`)로 저장하고 `evidence.screenshot`이 그것을 가리키게 한다 — 첫 세션이 만들고 이후 세션은 실행만. 스크립트가 깨지면 그 자리에서 고치되, 고친 버전을 스크립트에 되반영하는 것까지가 한 동작.

## 2. 캡처 규칙 (스택 무관)
- **상태 재현은 선언된 경계 mock**(`mock.boundary`)의 핸들러를 재사용한다. 캡처용 즉석 서버·별도 mock 파일 금지 — 테스트 mock과 이중화되어 드리프트한다(2026-08-25 리뷰가 실제로 지적).
- **대상 식별자 고정**: 캡처 대상(브라우저 컨텍스트·시뮬레이터 기기)은 세션 시작에 식별자로 1회 고정하고 전 과정에서 재사용한다. "지금 떠 있는 것"에 의존하면 재캡처 때 다른 대상이 잡혀 좌표·해상도가 전부 어긋난다.
- **조작 자동화 전 포커스 고정**: 셸 호출이 터미널로 포커스를 가져가는 환경에서는 매 조작 배치 직전에 대상 앱 활성화를 명령에 포함한다. 첫 클릭 유실은 대부분 이것이다.
- **입력 텍스트는 타이핑 이벤트로**: 클립보드 경유 붙여넣기는 잔존값이 들어갈 수 있다 — 실패하면 잘못된 값이 증거에 남는다.
- **확인 다이얼로그**(권한·딥링크 등 OS 레벨): 자동화로 뚫으려고 반복하지 않는다. 1회 사용자 클릭을 요청하는 것이 정답이고, 그 사실을 증거 문서에 한 줄 남긴다.
- **증거 파일 규약**: `.claude/state/evidence/<change-slug>/`(**gitignored — 저장소에 커밋하지 않는다**, adr/0027; 저장소에 남는 시각 파일은 qa-cgamja baseline뿐) 아래 `<화면>-<뷰포트|기기>-<라이트|다크>[-<상태>].png`. 캡처 직후 이미지 Read로 **내용을 확인**하고 기록한다 — "찍었다"가 아니라 "무엇이 보인다"가 증거다(2026-08-25 자체 판정 오류: 코드와 모순되는 "OK" 표 재발 방지).
- **장수 규율(adr/0025)**: 상태당 캡처 1장. 캡처→Read→판정 기록을 한 번에 끝내고 **같은 이미지를 다시 읽지 않는다** — 읽은 이미지는 세션 끝까지 컨텍스트에 남아 이후 모든 요청을 불린다. 육안 재조정(위치·배율) 루프는 **상한 3회** — 넘으면 현재 상태로 증거를 남기고 잔여 편차를 문서에 한 줄 적는다(14라운드 재조정 실측 재발 방지). 재캡처는 상태가 실제로 바뀌었을 때만.
- **선언 밖은 찍지 않는다**: `evidence.dark: false`·`evidence.platforms` 밖 플랫폼은 시도하지 않고, PR·리뷰에 "선언된 한계"로 적는다(adr/0021 결정 3).

## 3. 실패 모드 → 대응
| 증상 | 대응 |
|---|---|
| 첫 클릭이 씹힘 | 조작 배치 앞에 대상 앱 활성화 명령 고정(§2) |
| 재캡처 좌표 전부 어긋남 | 대상을 이름이 아니라 식별자로 고정했는지 확인(§2) |
| 입력 필드에 엉뚱한 텍스트 | 클립보드 경유 금지 — 타이핑 이벤트로(§2) |
| 상단·하단 요소 클릭 실패 | 안전영역 보정 — 화면 좌표가 아니라 요소 실측 중심으로 |
| 소프트 키보드가 안 뜸 | 시뮬레이터의 하드웨어 키보드 연결 설정 확인(§4) |
| 캡처 화면이 낡은 상태 | 앱 리로드 후 상태 재주입 — 캐시된 화면을 증거로 쓰지 않는다 |
| 같은 다이얼로그에 자동화 3회 실패 | 사용자 1회 클릭 요청으로 전환(§2) |

## 4. 검증된 구현
### iOS 시뮬레이터 (macOS, 2026-08-25~26 실측 — 대상 앱 레포 Tier-2 2런)
- **캡처**: `xcrun simctl io <UDID> screenshot <path>.png` — `booted` 대신 **UDID**를 쓴다. 같은 이름의 기기가 여럿 부팅될 수 있고, `booted`는 재캡처 때 다른 기기를 잡았다(좌표 전면 불일치의 실제 원인). UDID는 세션 시작에 `xcrun simctl list devices booted`로 1회 확보.
- **조작**: `cliclick`(클릭·타이핑) + 매 배치 직전 `osascript -e 'tell application "Simulator" to activate'` 고정 — 셸 호출마다 터미널이 포커스를 가져가 첫 클릭이 유실된다(실측).
- **좌표**: 시뮬레이터 창 좌표 ≠ 앱 좌표. 안전영역(노치·홈 인디케이터)을 보정하고, CTA처럼 중요한 타깃은 스크린샷을 먼저 읽어 실측 중심으로 클릭한다.
- **키보드**: 소프트 키보드가 안 뜨면 Simulator의 하드웨어 키보드 연결(I/O > Keyboard > Connect Hardware Keyboard)을 끈다. 텍스트 입력은 `cliclick t:`(타이핑) — 클립보드 붙여넣기는 기기 클립보드 잔존값이 들어간 실측 사고가 있다.
- **다이얼로그**: 개발 클라이언트 딥링크 확인 등 OS 다이얼로그는 자동화가 자주 막힌다(macOS 권한) — 1회 사용자 클릭 요청이 검증된 경로.
- **상태 재현**: 선언된 경계 mock 핸들러 재사용. 즉석 mock 서버는 리뷰에서 이중 mock 드리프트로 지적됐다.
### 웹 (2026-08-21 실측)
- `agent-browser` 또는 E2E 러너의 스크린샷 기능(`references/platform-fit-frontend.md` §5). 뷰포트는 프로필 표.
