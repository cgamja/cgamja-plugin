# 4가지 질문 재검증 판정 (2026-08-21)

질문: ① CE를 안 쓰는가 ② TDD를 어떻게 하는가 ③ 규칙은 어디에 ④ 아키텍처는 어디에·무엇으로. 각각 "현재 결정을 반박하라"는 리서치를 돌린 결과. 반영 위치는 맨 오른쪽.

## ① CE vs OpenSpec 분담 — KEEP(형태) + CHANGE 2
| 검증 항목 | 판정 | 근거 | 반영 |
|---|---|---|---|
| ce-plan은 OpenSpec change와 "같은 자리" | KEEP | ce-plan 산출물(R/A/F/AE/U ID 플랜)은 change 아티팩트와 중복. lfg는 `docs/plans` 하드 의존 | adr/0001 |
| ce-work도 같은 자리 | **CHANGE(전제 수정)** | ce-work는 *루프*만 겹치고, opsx:apply에 없는 **증거 계약**(red 관찰·verification_evidence)·멱등성(이미 된 유닛 재구현 금지)·simplify 패스·리뷰 꼬리를 갖는다. 우리 workflow.md가 그걸 산문으로 재구현 중 — "재구현 금지"를 ADR이 스스로 어김 | adr/0001 전제, 실험 B |
| ce-code-review가 플랜 없이도 동작 | **CHANGE** | `docs/plans/*` 또는 `## Requirements` R-ID만 찾음. OpenSpec `### Requirement:`는 인식 못 함 → **Requirements Completeness 섹션이 조용히 빠지고** "요구사항 누락" 판정이 영영 안 나옴. 나머지(정확성·테스트·보안·solutions 조회)는 정상 | workflow 2-5, openspec-setup archive guidance |
| ce-compound / brainstorm | KEEP | compound는 plans 의존 0. brainstorm 산출물은 proposal 입력으로 충분 | — |
| ce-work에 tasks.md 먹이기 | UNSURE | legacy plan으로 읽긴 하나 **체크박스를 무시하고 안 찍는다** → `openspec status` 0/N. `mode:return-to-caller` + 체크박스 수동 반영 브리지는 가능(superpowers-bridge 선례). 2개 change 실험 후 결정 | adr/0001 실험 B |
| 남들이 둘을 같이 쓰나 | KEEP | 공개 필드 리포트 0. 유일한 검증된 패턴 = "한 도구가 아티팩트 소유, 다른 도구는 schema `instruction`에서 호출" | — |
| 살아있는 스펙은 썩는가 | KEEP(트리거 교체) | 에이전트는 스펙을 **읽는다**(Imoto: "현실 대신 스펙에 충실"). 위험은 안 읽는 게 아니라 **오래된 걸 믿는 것**. 따라서 "20 change 동안 안 읽음" 트리거는 잘못 측정 → "스펙이 테스트된 동작과 모순된 채 출하 2회"로 교체 + CI `openspec validate --archived` | adr/0001 재검토, workflow 7 |

## ② 프론트 TDD — CHANGE 4, KEEP 3
| 항목 | 판정 | 근거 | 반영 |
|---|---|---|---|
| 인터랙션 = jsdom+RTL+user-event | **CHANGE** | Vitest 4 Browser Mode 안정화; Kent C. Dodds "jsdom 안 쓴다"; `@testing-library/user-event` 메인테이너가 "새 브라우저 테스트엔 쓰지 말라"(2026-08); jsdom 자체 유지보수 모드. 단 CI 취약(Chromium 메모리 누수 #9437, iframe 행) → 두 프로젝트 분리 + 파일명 라우팅 | tdd §1 |
| TDD가 에이전트 UI 품질을 올린다 | **CHANGE(재정의)** | Böckeler 통제 비교: TDD/비TDD 품질 차이 없음, 토큰 3~8.5배. 에이전트는 red를 건너뛰거나 위조. 근거 있는 가치는 ① 실패 테스트 = 사람이 30초에 리뷰하는 스펙 ② 커밋된 읽기전용 테스트 = 변조 방지(ImpossibleBench: 읽기전용이면 테스트 변조 치팅 제거) | tdd §0, adr/0004 |
| red 단계 강제 | CHANGE(메커니즘) | 요청으론 안 됨. PreToolUse로 `*.test.*` 편집 차단(`TDD_PHASE=red` 제외), `it.skip/.only/expect(true)/vi.mock(src/**)` 거부, 독립 리뷰어 | tdd §2, §4 |
| Storybook 스토리=테스트 | UNSURE→선택 | 공식 입장이나 솔로엔 둘째 설정면. 있으면 addon-vitest로 중복 제거, 없으면 테스트 목적만으로 도입 금지 | tdd §3 |
| MSW만 | KEEP+구체화 | 한 handlers.ts를 jsdom(setupServer)/browser(setupWorker fixture)/E2E(@msw/playwright) 공유. Chromium 전용(vi.mock+SW 수정이 Chromium만). vi.mock과 혼용 금지 | tdd §3 |
| Stryker 도메인만 | KEEP(이유 수정) | Browser Mode 미지원이라 **강제된** 선택. 매 턴엔 정적 게이트(`eslint-plugin-vitest` expect-expect 등 + captain-obvious) | tdd §5 |
| E2E 2~3개 / Playwright CT | CHANGE | 3~5개로, 이름 지정. `@playwright/experimental-ct-*`는 **삭제됨**(2026-08) — 언급 금지 | tdd §1 |
| test 커밋 → feat 커밋 | KEEP(핵심 통제로 승격) | thoughtbot·npf.io 실천, 사람 게이트 + 변조 증거. 무인이면 "stage + 훅 차단" | tdd §2 |

## ③ 규칙 배치 — KEEP 2, CHANGE 4
| 항목 | 판정 | 근거 | 반영 |
|---|---|---|---|
| CLAUDE.md ≤60줄 | KEEP(soft) | Anthropic 200줄, OpenAI 100줄. **단** McMillan 2026(1,650세션): 25~500줄 사이 준수율 차이 없음 — 짧은 파일은 컨텍스트 예산용이지 준수율용 아님. 드리프트는 세션 내(함수 1개당 5.6% 감소) → 훅으로만 해결. `/doctor`는 폴더맵·의존성 목록을 "유도 가능"으로 잘라냄 | conventions §3 |
| `@docs/conventions.md` import | **CHANGE** | `@import`는 **eager**(런치 시 전부 로드) → 60+100=160줄. 백틱 경로는 lazy | conventions §1,§3 |
| 판단 규칙을 conventions.md에 | **CHANGE** | 파일 타입별 규칙은 `.claude/rules/*.md` + `paths:` (해당 파일 읽을 때 재주입 = 결정 시점 재고정). 스킬은 56% 미호출(Vercel). conventions.md는 이유+예시 파일 포인터만. compaction 후 path-scoped rule은 재주입 안 됨(→ "절대" 규칙은 훅) | conventions §1 |
| 훅 > 산문 | KEEP+강화 | Write/Edit 훅은 `tee`/`sed -i`로 우회됨(#63786) → Bash 매처+`FileChanged`+`permissions.deny`. `if` 필터는 fail-open. PostToolUse는 파일 단위 1초 이내, 전체는 Stop. Stop 8회 차단 후 강제 종료 | conventions §5 |
| commitlint | KEEP+가드 | Opus 4.6이 `--no-verify` 6연속 우회 사례(#40117, CLAUDE.md에 금지 있었음) → 훅+deny+CI commitlint. 대화형 훅 금지, `GIT_PAGER=cat` | conventions §5 |
| DoD 위치 | **CHANGE** | 단일 소스 `pnpm verify` 스크립트 → Stop 훅이 실행 → CLAUDE.md 한 줄 → OpenSpec guidance는 스크립트 이름만 참조 → CI 동일 | conventions §1, workflow 3-1, openspec-setup |
