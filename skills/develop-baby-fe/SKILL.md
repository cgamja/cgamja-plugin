# develop-baby-fe

MVP에는 절차의 무게가 곧 비용이다. 이 스킬은 develop-fe의 하위 티어가 아니라 **분리된 진입점**이다(adr/0020): 성능·완전성보다 비용·속도, 리뷰와 검증은 최소한만. Tier-1 패치($0.74)와 Tier-2 풀 절차($30~45) 사이의 빈 구간을 채우고, **목표 비용은 작업당 $5 미만**이다.

## 언제 이 스킬 / 언제 develop-fe

| | develop-baby-fe | develop-fe |
|---|---|---|
| 대상 | MVP, 프로토타입, 데모, 실험, 해커톤 | 프로덕션 레포, 티켓 기반 작업 |
| 우선순위 | 비용·속도 | 정확성·증거·스펙 유지 |
| 스펙 | 없음 | OpenSpec change |
| 테스트 | 기존 초록 유지만 | red 게이트 → 구현 |
| 리뷰 | L1 정확성 1회 | 리뷰 2축(review-cgamja + code-review) |
| 비용 | <$5 | Tier-2 ≈$30~45 |

프로젝트 선언(`.claude/cgamja.json`)에 `"mode": "baby-default"`가 있으면 그 프로젝트의 코드 변경 요청은 기본으로 이 스킬로 진입한다 — 프로토타입 레포에서 매번 "MVP로"라고 말하지 않기 위한 선택 키다(사용자가 손으로 넣는다; 세팅 스킬은 묻지 않는다). **단, 표의 develop-fe 열 조건(프로덕션 티켓·API 계약 신설·다중 화면)은 `baby-default`보다 항상 우선한다** — 선언이 있어도 그 요청은 develop-fe로.

## 절차 — 6단계, 사람 게이트는 1번의 질문 1회뿐

1. **탐색 + 질문 최대 1회**: 관련 코드와 기존 컴포넌트·유틸 grep — 있으면 재사용, `V2` 금지. 프로젝트 선언이 있으면 읽고, 없어도 멈추지 않는다(세팅 안내 없음 — MVP는 세팅보다 먼저일 수 있다). 질문은 AskUserQuestion 1회에 묶어서 내가 가정한 기본값 목록의 반박만 받는다 — 코드가 이미 답하는 건 묻지 않고, 없으면 질문 생략.
2. **구현**: 바로 만든다. 빈·로딩·에러 상태는 스펙이 없어도 기본 포함(싸고 나중에 비싸지는 것만 챙긴다).
3. **정확성 리뷰 1회**: `agents/reviewer-correctness.md` persona 서브에이전트 1개, **`model: sonnet` 명시**(비용 우선 — adr/0011 기본 opus에서 의도적 하향, adr/0020 결정 7). blocker만 고치고 리뷰 재실행 없이 끝. 즉석 리뷰어 제작 금지는 여기서도 유지.
4. **verify 1회** (blocker 수정까지 끝난 **최종 코드에서**): `commands.verify`(선언; null이면 `commands.typecheck`→`commands.test` 순으로 대체, 전부 null이면 **생략하고 그 사실을 보고**). 기존 테스트가 깨지면 고치기 전엔 완료가 아니다. 리뷰보다 뒤인 이유: 리뷰 반영 diff가 검증 없이 커밋되는 걸 막는다.
5. **스크린샷 1장**: 실행 화면 1장(뷰포트 1개, `evidence.screenshot` 선언 또는 가능한 수단). 수단이 없으면 생략하고 보고 — 매트릭스(뷰포트×다크×키보드)는 만들지 않는다.
6. **커밋 1~3개**: 단계 단위(`feat(scope):` 구현 / 필요하면 `fix(scope):` 리뷰 반영 / `chore(scope):`), Angular + 한국어. PR·푸시는 사용자가 요청할 때만.

## 유지하는 최소 규칙 (MVP가 살아남을 때의 하한선)
- 계약 생성물이 선언돼 있으면(`contract.generated`) **생성물만 import** — 손 타입·직접 HTTP 호출 금지. 살아남은 MVP의 retrofit 비용 절반이 여기서 갈린다(adr/0008).
- **기존 테스트는 초록 유지.** 깨뜨린 채 완료 보고 금지. 단, 새 테스트를 쓰지는 않는다.
- **새 의존성은 질문** 후에만.
- 만들기 전에 grep — 중복 컴포넌트가 에이전트 1위 실패다.

## 에스컬레이션 — 멈추고 안내한다 (자동 전환 아님)
다음 순간이 오면 작업을 멈추고 지금까지의 diff를 요약한 뒤 `/develop-fe`를 안내한다:
- **API 계약을 새로 만들거나 바꿔야 할 때** — 계약 결함은 리뷰가 실버그를 잡아온 지점이다
- **여러 화면·공유 상태가 엮일 때** — 상태 배선 버그도 마찬가지
계속 baby로 갈지는 사용자가 정한다. "일단 mock으로 돌아가게"를 고르면 그 사실을 커밋 메시지에 남긴다.

## 절대 하지 않는 것
- 티어 판정, OpenSpec change 생성, red 게이트, 리뷰 축 추가·재실행, 증거 매트릭스, ce-* 호출
- Figma 스냅샷 절차 — `design/` 스냅샷이 이미 있으면 참고만 하고, 없다고 만들지 않는다
- 리뷰를 같은 관점으로 반복(self-consistency) — 반복은 돈 낭비라는 실측이 있다(adr/0020 맥락)
- 이 스킬로 프로덕션 티켓 작업 — description의 배타 트리거를 지킨다
