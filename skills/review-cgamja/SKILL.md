# review-cgamja — 코드 + SEO 종합 리뷰

`review-code`와 `review-seo`를 순서가 아니라 **동시에** 돌리는 오케스트레이터다. 두 스킬의 절차는 각 SKILL.md가 원천이니 그것을 읽고 따르되, 여기서는 둘을 한 세션에서 돌릴 때만 생기는 일을 다룬다.

## 1. 축 정하기

- 코드 축: 변경분이 있으면 항상.
- SEO 축: 프로젝트에 공개 웹 페이지가 있고, 변경이 페이지(마크업·메타·문안·움직임·폰트·이미지·라우트)에 닿았을 때. 순수 내부 로직·API·앱(RN) 변경이면 뺀다. 사용자가 "SEO 최우선"이라 한 프로젝트면 기본 켬. `--seo-only`/`--code-only`는 그대로 따른다.

## 2. 한 메시지에 전부 스폰

리뷰어(reviewer-cgamja · 정확성)와 골라 둔 claude-seo 에이전트를 **같은 메시지**에서 띄운다. SEO 에이전트는 빌드 결과를 로컬로 띄운 URL이 필요하므로, 스폰 전에 빌드·서빙(`review-seo` 1단계)을 먼저 한다. 다 뜨는 데 5분쯤 걸린다 — 그동안 기준선 숫자(`inspect_html.py`)와 스크린샷을 찍어 둔다. 결과를 예측해서 미리 고치지 않는다.

## 3. 합쳐서 고치기

보고가 다 오면 한 번에 고친다. 축이 둘이라 생기는 일:

- **같은 파일을 두 축이 가리킨다.** 예: 애니메이션 컴포넌트 — 철학은 "경로 분리·상수 이름", SEO는 "초기 HTML에 숨김 상태 금지". 둘 다 만족하는 구조로 한 번에 고친다(마운트 게이트를 넣으면서 reduce 경로도 얼리 리턴으로).
- **우선순위는 사용자 선언을 따른다.** "SEO 최우선"이면 디자인·움직임보다 SEO가 이기고, 그 결정을 ADR에 남긴다. 선언이 없으면 blocker(빌드·정확성·색인 차단) → 철학 should → SEO high → 나머지.
- **사실·문안·정책 판정은 모아서 한 목록으로.** 회사 표기, 가격, 제목 길이, 크롤러 정책, 문서에 규칙이 없는 영역 — 고치지 않고 넘긴다.
- **재검사는 축마다 1회.** 철학은 reviewer-cgamja 재검사, SEO는 `inspect_html.py` 전후 비교와 브라우저 콘솔 0건. 전체 에이전트를 다시 돌리지 않는다.

## 4. 검증·커밋·보고 한 번

- 프로젝트 검증 명령 한 번(`pnpm verify` 등). 개발 서버가 빌드에 죽었으면 다시 띄운다.
- 커밋은 의도별로(COMMIT.md). 두 축의 수정이 파일을 공유해 못 나누면 한 커밋에 두고 본문에 축별로 적는다. 결정은 ADR 개정으로.
- 보고 하나:

```
## 종합 리뷰 — <범위>
**철학**: 판정 · 위반 n/m 수정 · 남은 것
**정확성**: 확인 n · 추정 n
**SEO**: 가장 큰 문제 하나 · 고친 것 · 기준선→결과
**팀 판정 필요**: (축 구분 없이 한 목록)
**사이트 밖**: 있을 때만
```

## 주의

- 에이전트 5~6개가 동시에 도니 토큰이 40~50만 든다. 작은 변경(한 파일)에는 `review-code`만 쓴다.
- 두 축의 보고를 따로따로 붙여 넣지 않는다. 사용자는 "무엇을 고쳤고 무엇을 정해야 하는지" 한 장을 원한다.
- 플러그인 `cgamja:review-cgamja`(철학 게이트 전용)와 이름이 같다. develop-fe 워크플로우 안에서는 플러그인 것이 돌고, 사용자가 직접 부를 때는 이 종합판이다.
