# retro-fe

스킬이 실제로 어떻게 굴러갔는지는 **트랜스크립트가 원장**이다. 이 스킬은 그 원장을 읽어 마찰을 측정하고, 재검토 조건(develop-fe `workflow.md` 7장)에 데이터를 공급하고, 제안을 낸다. **여기서 절차·훅을 고치지 않는다** — 같은 이탈 2회 = ADR 새 번호(adr/README 규약)이고, 이 스킬의 산출물은 그 ADR의 **근거 자료**다(`adr/0022`).

## 입력 — 세션 트랜스크립트
- 위치: `~/.claude/projects/<프로젝트 슬러그>/*.jsonl` — 슬러그는 대상 프로젝트 절대경로의 `/`를 `-`로 바꾼 것(예: `/Users/x/app` → `-Users-x-app`). **현재 작업 중인 프로젝트의 디렉터리만 연다** — 다른 프로젝트·개인 대화는 열지 않는다.
- 구조(JSONL, 줄마다 JSON 하나): `type`(`user`/`assistant`/`system`), `message.content`(문자열 또는 블록 배열 — `text`/`tool_use`/`tool_result`), `timestamp`. 마찰 마커: tool_result의 `is_error: true`, user 텍스트의 `[Request interrupted by user]`, 훅 출력의 `permissionDecision`(`deny`/`ask`)과 사유 문자열(`[protect]`/`[tdd]`/`[stop]` 접두). 파싱이 깨지면 포맷이 바뀐 것 — 구조부터 재확인하고 이 절을 갱신 제안한다.
- 선택: 기본 **최근 4개 중 대상 스킬이 로드된 세션**(`grep -l "skills/develop-fe" *.jsonl` 류로 판별 — 파일명·크기·mtime만 본체가 본다). 사용자가 기간·개수·세션을 지정하면 그대로.

## 절차
1. **세션 선택** (본체): 위 grep + `ls -lt`. 세션마다 크기·날짜·첫 사용자 요청 한 줄을 표로 보고하고 대상 확정. 수 MB 파일을 본 컨텍스트에 읽지 않는다.
2. **세션당 분석 서브에이전트 병렬** — `model: sonnet`(루브릭이 정해진 분류·집계, `docs/guides/model-routing.md` §1). 같은 메시지에서 동시에 띄우고, 각 에이전트에 §신호 목록과 트랜스크립트 경로·구조 설명을 넘긴다. 반환: 세션 개요(요청·경과·산출물) + 신호별 집계 + 증거 인용(판정에 필요한 최소만) + 스킬 설계 / 모델 행동 / 프로젝트 세팅 3분류.
3. **집계** (본체): 세션 간 같은 신호를 합치고(같은 훅 사유 문자열 = 같은 결함), 빈도·소요 시간 낭비 순으로 정렬.
4. **재검토 조건 대조**: develop-fe `workflow.md` 7장(+ 각 ADR의 "재검토 조건" 절)의 조건마다 발동/미발동/데이터 부족을 표시. 발동 근거는 3의 집계 행을 가리킨다.
5. **제안**: 발동된 조건마다 ADR 후보(제목 + 한 줄 근거 + 고칠 파일 목록)를 적는다. 리뷰 신호(지적 반영률·축별 "없음" 연속)는 `reports/lens-ledger.md`(adr/0016 — v1 렌즈 원장을 리뷰 2축 원장으로 이어 쓴다)에 추가할 행을 **제안**한다 — 직접 쓰지 않는다.
6. **기록**: `reports/retro-<날짜>.md`(플러그인 레포. 규약은 `reports/README.md` — 런 비교표에 한 줄 추가). 보고 맨 위에 판정 한 줄: "세션 n개 · 마찰 m건 · 재검토 조건 발동 k개 · ADR 후보 j개".

## §신호 — 세션당 분석이 세는 것 (신호 → 입력이 되는 재검토 조건)
| 신호 | 어떻게 세나 | 어느 조건의 입력 |
|---|---|---|
| 훅 deny/ask 횟수·사유 | `[protect]`/`[tdd]`/`[stop]` 사유 문자열별 집계, 오탐(읽기 전용 명령 차단 등) 별도 표시 | "훅을 우회하는 습관" · adr/0009 "ask 10회 이상 피로" |
| 사용자 인터럽트·정정·되물음 | `[Request interrupted by user]`, 직전 어시스턴트 행동을 뒤집는 사용자 메시지, 같은 질문 2회 | 게이트·보고 설계 전반 |
| 같은 명령 재시도 루프 | 같은 도구+유사 입력 연속 실패 2회 이상 | "같은 수정 2번 실패 → /clear" 준수 여부 |
| 게이트·절차 이탈 | 스킬 절차(티어 판정, red 먼저, 증거, 리뷰)와 실제 순서의 diff, 우회 명령(`git clean` 등) | adr별 재검토 조건 |
| 도구 오류 | `is_error: true` 사유별 | 세팅·환경 결함 |
| 시간 | 세션 총 소요, 첫 가시 텍스트까지, 단계별(스펙/red/구현/증거/리뷰) | "스펙 작성이 구현보다 오래 2번" 등 |
| 커밋·컨텍스트 | 커밋 수/PR, 승인 프롬프트 수, (기록 있으면) 컨텍스트 사용률 | 커밋 정책·컨텍스트 규칙 |
| **산출물 ↔ rules 대조**(adr/0031) | 트랜스크립트가 아니라 **레포**를 본다: `.claude/rules/*.md`·CLAUDE.md의 각 항목을 실제 코드·증거 파일과 대조. 특히 **부재**를 본다(찍지 않은 스크린샷, 돌지 않은 명령, 가리키는데 없는 경로) | adr/0031 재검토 조건 |
| **정지 원인 분류**(adr/0029) | 5분 이상 공백마다 직전 이벤트가 정지 허용 목록 a~e 중 무엇인가 — 어디에도 없으면 **이탈 1건**. 사람 대기가 세션에서 차지하는 비중도 함께 | adr/0029 재검토 조건 |

## 절대 하지 않는 것
- workflow.md·SKILL.md·훅·references 직접 수정 — 제안까지만, 반영은 ADR(사람)
- 트랜스크립트 원문 대량 인용·본 컨텍스트 덤프 — 서브에이전트가 파싱하고 증거는 최소 인용만
- 다른 프로젝트 세션 열람, 사용자 개인 메시지의 판정 외 인용
- 마찰 0건인데 억지로 제안 만들기 — "발동 조건 없음"도 유효한 결과다
