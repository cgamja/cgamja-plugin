### 3-1. `review_nudge.sh` — 오탐과 미탐이 한 원인에서 나온다 (확정)

```bash
d="$(j tool_input.subagent_type) $(j tool_input.description) $(j tool_input.prompt)"
grep -qiE 'review|리뷰|코드 ?검토' <<<"$d" || exit 0
grep -qE 'reviewer-cgamja|agents/reviewer-' <<<"$d" && exit 0   # 정상 경로 예외
```

예외 목록이 `reviewer-cgamja`만 안다. 결과:

- `cgamja:reviewer-correctness`(정상 L1 렌즈) → 예외에 안 걸려 **매번 오발동**(저녁 4회)
- `cgamja:reviewer-cgamja`를 Agent로 직접 호출 → 예외에 걸려 **통과**. 정작 "스킬로 부르라"고 막아야 할 케이스를 놓쳤다(19:xx `landing-benefit`, 20:xx `landing-demo`)
- 회고용 트랜스크립트 분석 Agent → 프롬프트에 "리뷰"가 있다는 이유로 **오발동**(3회)

두 세션 분석이 각각 "비일관성, 훅 소스 확인 필요"로 남긴 것을 소스 대조로 확정했다. 목적(리뷰를 *수행*)과 소재(리뷰를 *언급*)를 구분하지 못하는 전문 substring 매칭이 근인이다. ADR 0028이 오늘 `protect-bash.sh`의 같은 계열 결함을 고쳤으나 이 훅은 손대지 않았다 — **문자열 매칭 오탐 5회차**.

### 3-2. 리뷰 축 침식 (저녁)

`Skill cgamja:review-cgamja` 호출은 저녁 3개 change 중 **1회뿐**(landing-hero). benefit·demo는 `Agent`로 `reviewer-cgamja`를 직접 띄웠다. 결과물 품질 차이는 관측되지 않았으나(각 change마다 blocker 수정 패스 1회 정상 수행), 게이트가 스킬 밖으로 새면 재검사 1회 상한·`fix(review)` 커밋 규칙이 훅의 사정권을 벗어난다. 3-1의 미탐이 이걸 방치했다.

### 3-3. bypassPermissions (오후)

세션 전 구간이 `permissionMode: "bypassPermissions"`. CLAUDE.md가 전제하는 "사람이 diff를 보고 승인"이 원천적으로 성립하지 않았다. 모델이 13:52에 스스로 감지·고지하고 red 게이트는 "실패 출력 원문 보고"라는 문서화된 대체 절차로 전환했으나, **protect-file ask 18건에는 대체 절차가 없어 무검증 통과**했다. `workflow.md` 0장에 permission mode 점검이 없다.

### 3-4. 개발 중 재귀 회고 (오후)

`develop-fe`의 "10 task마다 재검토" 조건이 15:53에 발동해 세션 안에서 `retro-fe`가 자기 자신을 감사했다(19분 + 전후 8분 = 약 27분). 절차 위반은 아니지만 개발 흐름 한가운데서 발동해 change 사이가 아닌 지점을 끊었다.

### 3-5. `--overwrite ignore`로 PRD.md 삭제 (오후, 복구됨)

## 5. ADR 후보

| # | 제목 | 근거 | 고칠 파일 |
|---|---|---|---|
| A | **`review_nudge` 예외 목록과 목적 판별** — `reviewer-correctness` 누락(오탐)과 `reviewer-cgamja` 직접 호출 통과(미탐)를 함께 고친다. 판정 대상을 프롬프트 전문이 아니라 `subagent_type`으로 좁힌다 | §3-1, 누적 10회, 오탐 5회차 | `hooks/review_nudge.sh` |
| B | **세션 시작 0장에 permission mode 점검 추가** — bypass면 red 게이트·protect ask 대체 절차를 *시작 시점에* 선언 | §3-3, ask 19건 무검증 통과 | `workflow.md` 0장, `hooks/setup_check.sh` |
| C | **차단형 질문 → 가정 명시 진행으로 기본값 전환** — 사람 대기가 지배적일 때 게이트가 정지 대신 전진하게. "디자인 미확정"은 2-D 갭 루프로 자동 진입하고 사후 확인 | §2 최상위 발견, 110분 정지 후 답변 2건 모두 위임 | `workflow.md` 1장·2장 2번, 2-D |

우선순위는 **C > D > A > B > E**. C가 오늘 잃은 110분의 직접 원인이고, D 없이는 C가 회수한 시간을 병렬로 쓸 수 없다.

## 6. 병렬 개발 준비 상태 (사용자 목표)

`workflow.md` 2-P가 요구하는 것 대비 현재 레포:

| 항목 | 상태 |
|---|---|

| `.worktreeinclude` (worktree별 `.env`) | **없음** |
| `.claude/worktrees/` + gitignore 항목 | **없음** |
| dev 서버 포트 분리 | **없음** — `vite.config.ts`에 `server.port` 미지정, 전부 5173 |
| 머지 이력 | 머지 커밋 0, main 일직선 |

병렬 가능 판정 4개 중 현재 걸리는 것: **판정 3(환경 싱글턴 — 포트 하나)**. 판정 2(semantic 표면)는 change를 어떻게 자르냐에 달렸다 — 오늘처럼 모든 섹션이 `App.tsx`·`tokens.css`·`styles/contrast.test.ts`를 공유하면 직렬이 맞다.

**결론**: 기계적 격리(D)는 반나절이면 깔 수 있으나, 그것만으로는 오늘의 하루가 줄지 않았을 것이다. 오늘 직렬을 강제한 것은 워크트리 부재가 아니라 사람 대기 181분이었고, 그건 C가 다룬다. 병렬 세션을 띄워도 사람이 두 세션의 차단형 질문에 모두 답해야 하면 대기는 줄지 않고 컨텍스트 스위칭만 늘어난다.
