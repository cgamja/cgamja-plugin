## PR Convention

### 원칙

- **작게 낸다** — PR 하나 = 목적 하나. 리뷰어가 한 번에 이해할 맥락이 적을수록 좋다 (가독성 원칙을 PR에도 적용)
- **"왜"를 쓴다** — 코드는 diff가 보여주니까, 본문에는 코드로 표현 못 하는 것(배경, 선택한 이유, 하지 않은 것)을 쓴다. 주석 철학과 동일
- 제목은 커밋 컨벤션과 동일한 형식 (`feat: ...`, 한국어, 50자 이내)
- 스크린샷/녹화 — UI 변경이면 필수 (before/after)
- 리뷰어가 판단할 수 없는 건 PR에 남기지 말고 코드로 해결한다 — "이렇게 해도 될까요?"가 3개 이상이면 PR이 아니라 설계 논의가 먼저

### 본문 구성

1. **왜 하는가** — 배경·문제 (이슈 링크)
2. **무엇을 했는가** — 변경 요약 (파일 나열 말고 의도 단위로)
3. **왜 이렇게 했는가** — 다른 선택지를 버린 이유, 트레이드오프
4. **하지 않은 것** — 의도적으로 범위에서 뺀 것 (scope 명확화)
5. **확인 방법** — 테스트, 스크린샷, 재현 절차
