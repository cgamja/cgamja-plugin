# ADR 0028 — 훅 판정을 "명령 텍스트"에서 "명령의 대상"으로

- 상태: 채택 (2026-08-31)
- 관련: adr/0017(정밀화 1차), adr/0023(정밀화 2차), reports/retro-2026-08-31.md

## 문제

`protect-bash.sh` 의 오탐이 **네 번째** 재발했다(2026-08-26 · 08-27 · 08-27audit · 08-31). 두 번의 정밀화(0017 따옴표·읽기/쓰기 구분, 0023 세그먼트 판정)를 거쳤는데도 계열이 남는다.

2026-08-31 런에서 실측한 4건은 원인이 하나다 — **명령이 무엇을 건드리는가**가 아니라 **명령 문자열에 무엇이 적혀 있는가**로 판정한다:

| 차단된 명령 | 왜 걸렸나 |
|---|---|
| `npm install 2>&1 \| tail -4` | `2>&1` 의 `2>` 가 패키지명 인자로 매칭 |
| `cat > tasks.md <<EOF … .claude/hooks/… … <develop-setup>/… EOF` | heredoc **본문**의 파일명 + 플레이스홀더의 `>` |
| `cat > /tmp/scratch/probe.test.tsx <<EOF` | 프로젝트 **밖** 절대경로가 `**/*.test.tsx` 에 매칭 |
| 스크래치패드에서 `npm rm <pkg>` | 의존성 명령은 디렉터리 무관 차단 |

세 번째까지가 오탐이고, 네 번째는 설계상 의도적 보수성이다.

가장 나쁜 건 두 번째 줄이다 — 훅이 스스로 안내하는 복구 경로("승인 후 **인자 없는 install** 로 lockfile 동기화")를 훅이 자기가 막았다. 리다이렉트를 붙이는 순간 걸린다.

## 결정

판정 입력을 세 단계로 분리하고, 각 검사가 **자기에게 맞는 입력**만 본다.

| 변수 | 무엇을 걷어냈나 | 누가 쓰나 |
|---|---|---|
| `cmd` | 원본 | 우회 탐지(`--no-verify`, `TDD_PHASE=`), 인터프리터 실행 |
| `nohere` | heredoc 본문 | 아래 둘의 원천 |
| `stripped` | + 따옴표·fd 리다이렉트 | `core.hooksPath` 판정, rm 예외 |
| `pathsafe` | + **프로젝트 루트 밖 절대경로** | 경로 glob 매칭(`wseg`)**만** |
| `noopt` | nohere − 모든 리다이렉트 − 옵션 | 패키지 추가/삭제 탐지 |

원칙 세 줄:
1. **heredoc 본문은 데이터다** — 거기 적힌 파일명은 명령의 대상이 아니다.
2. **리다이렉트는 인자가 아니다** — 패키지 인자를 세기 전에 전부 걷어낸다.
3. **프로젝트 밖 경로는 이 프로젝트의 보호 대상이 아니다** — 단, 경로 매칭에만 적용한다.

### 3번의 적용 범위를 좁힌 이유 (구현 중 실측)

경로 제거를 *모든* 검사에 적용했더니 진짜 차단 3건이 뚫렸다:
- `git config core.hooksPath /dev/null` → `/dev/null` 이 사라져 **조회처럼** 보임
- `npm install > /tmp/x.log` → 리다이렉트 대상이 사라져 `>` 가 인자로 남아 오히려 deny
- 토큰을 공백으로 재조립하는 초기 구현이 인용·구분자를 망가뜨려 `sed -i '' …`, `pnpm add lodash` 가 통과

그래서 (a) `pathsafe` 는 `wseg` 전용이고 (b) 재조립이 아니라 **치환**이며 (c) 경로 시작을 공백·`>`·`=` 뒤로 한정해 `s/a/b/` 같은 sed 표현식 안의 슬래시를 건드리지 않는다.

## 버린 대안

- **정규식을 한 번 더 정밀화** — 세 번째 시도가 될 것이고, 앞의 둘이 같은 방식으로 실패했다. 문제는 정밀도가 아니라 판정 입력이다.
- **훅에서 실제 셸 파서를 쓰기**(`bashlex` 등) — 정확하지만 훅은 매 Bash 호출마다 도는 경로라 의존성과 지연을 늘릴 수 없다.
- **오탐을 감수하고 두기** — 네 번 재발했고 매번 우회 비용이 든다. 더 나쁜 건 에이전트가 "훅은 원래 시끄럽다"를 학습해 넛지를 무시하기 시작한 것이다(같은 런에서 advisory 1건 무시 실측).

## 비용

- heredoc·경로 제거에 `python3` 호출이 2회 늘었다. 훅은 Bash 호출마다 도므로 지연이 붙는다 — 체감 가능해지면 `_lib.sh` 에서 한 번에 처리하도록 합친다.
- 프로젝트 밖 경로를 통과시키므로, 에이전트가 의도적으로 절대경로를 써서 보호를 우회할 여지가 생긴다. 다만 그 경로는 이 프로젝트 파일이 아니므로 보호 대상 자체가 아니다.

## 강제 (이번 결정의 핵심)

**`skills/develop-setup/scripts/hook-cases.sh` 를 새로 만들었다.** 훅에 테스트가 없어서 회귀를 네 번 못 잡았다.

```
bash hook-cases.sh <project-dir> [hook-path]     # hook-path 로 설치 전 템플릿 검증
```

케이스 21개: 진짜 차단 10 · 읽기 통과 4 · 오탐 6 · 회귀 방지 1. 현재 **21/21**.
`smoke.sh` 의 훅 절(9종)은 그대로 두고, 이 표가 오탐 계열을 담당한다.

> 훅을 고칠 때는 **케이스를 먼저 추가해 빨강을 보고** 고친다. 이번 구현에서 그 순서 덕에 "고치다 진짜 차단 3건을 뚫은" 것을 즉시 잡았다.

## 재검토 조건

- 오탐이 또 나오면(5회차) 정규식 정밀화를 포기하고 셸 파서 도입을 재검토한다.
- `hook-cases.sh` 가 잡지 못한 오탐이 2회 나오면 케이스 표의 커버리지 설계를 다시 본다.
- 훅 지연이 체감되면 `python3` 2회 호출을 `_lib.sh` 한 곳으로 합친다.
