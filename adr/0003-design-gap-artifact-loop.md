# 0003. 미완성 디자인은 Artifact로 후보 → 확정 → 코드 먼저 → Figma엔 평면 캡처 거울만
- 상태: 제안
- 날짜: 2026-08-21
- 검증: (없음)

## 맥락
Figma 파일 일부는 와이어프레임에 디자인을 입히지 않은 상태로 남고, 사용자가 이를 표시해 둔다. 사용자 의도: Claude Artifact로 후보를 뽑아 같이 디자인하고, 확정되면 Figma에 씌운 뒤 개발. 리서치 결과 "Figma에 씌운다"의 두 경로 중 `use_figma`(인스턴스 재조립)는 이미지 불가·폰트 업로드 필요·20KB/호출·베타 품질이고, `generate_figma_design`(평면 캡처)은 안정적이지만 컴포넌트 연결이 없다. 구조적 양방향 동기화를 신뢰하는 사례는 없었다. `references/figma-design-source.md` §5.

## 결정
1. 표시(`📝 TODO:`/`🚧 WIP`/`⬜ PLACEHOLDER`)된 부분은 구현하지 않고 디자인 갭 루프로 보낸다.
2. 후보는 `design` 스킬(Claude Design 캔버스 Artifact)로 2~3안, 토큰·기존 컴포넌트만 사용, 와이어프레임 정보 구조 유지. 사용자가 캔버스에서 직접 수정·확정.
3. 확정본은 **코드로 먼저** 구현한다(Figma를 거치지 않는다). 결정 이유는 `design/screens/<slug>/summary.md`에 한 줄.
4. Figma에는 `generate_figma_design`으로 `🧩 Built-in-code` 섹션에 평면 캡처를 남긴다(`source: code · 날짜`). `use_figma`로 재조립하지 않는다. 재사용 컴포넌트로 승격될 때만 사용자가 Figma에서 수동 제작.
5. 그 뒤 스냅샷을 만들어 Ready 화면과 동일하게 취급한다.

## 전제
- 후보 디자인의 품질 기준은 "기존 Ready 화면과 같은 톤"이다 — 토큰·컴포넌트가 이미 코드에 있어야 한다(즉 디자인시스템 스냅샷이 선행).
- 사용자는 Artifact 캔버스에서 수정하는 것을 선호한다(Figma에서 다시 그리는 것보다).
- Full seat(캔버스 쓰기). 없으면 4단계 생략.

## 재검토 조건
- 사용자가 확정 후 Figma에서 다시 손보는 일이 반복(2회) → Artifact 대신 Figma에서 직접 후보를 만드는(`figma-generate-design`) 경로로 전환 검토.
- `generate_figma_design`이 라이브러리 컴포넌트로 해석하는 기능을 내놓음(포럼 요청 있음) → 4단계를 "진짜 동기화"로 승격.
- 후보 2~3안이 매번 한 안으로 수렴 → 1안 + 변형 포인트 제시로 축소.

## 결과 / 영향
- Figma의 `🧩` 섹션은 원천이 아니라 거울이다. 그 부분의 원천은 코드 + summary.md.
- 디자인 갭 하나당 Figma 호출: 입력 1~2회 + 캡처 1회.
