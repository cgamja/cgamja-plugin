# 0023. 훅 오탐 2차 정밀화 — heredoc·세그먼트 판정·advisory 1회·프로젝트 동기화 (0017 개정)

- 상태: 제안
- 날짜: 2026-08-27
- 관련: 0017(훅 정밀화 1차 — 본 ADR은 그 재검토 조건 "IWRITE 오탐/누락 각 2회" 및 "같은 이탈 2회 = 새 번호" 규약의 발동), 0014(선언), 0018(red 게이트 배치 승인)
- 검증 근거: retro-2026-08-27_audit — 세션 4개에서 deny 17건 중 오탐 12건(71%), 3회 연속 회고에서 훅 오탐이 최대 마찰 계열. 수정 후 재검증: 다음 Tier-2 change 1개에서 훅 deny 오탐 0·advisory 경고 세션당 ≤1회.

## 맥락
0017이 읽기/쓰기 구분을 도입했지만 회고 4회차에서 오탐이 오히려 늘었다(2계열→4계열). 원인은 세 겹이다:
1. **템플릿 미동기화**: 0017의 수정이 `templates/hooks/`에는 반영됐지만 실사용 프로젝트(~/app)의 `.claude/hooks/protect-bash.sh`·`verify-on-stop.sh`는 구판이었다 — hooksPath **조회** 차단·인터프리터 읽기 실행 차단이 08-27 세션에서 그대로 재발(ee7057d9 deny 9 중 오탐 6). 훅은 develop-setup이 심는 **사본**이라, 템플릿을 고쳐도 프로젝트가 낡은 채 남는 배포 경로 자체가 결함이다.
2. **신규 오탐 패턴 2종**(템플릿에도 존재):
   - `WRITE` 정규식의 `cat <<` — heredoc 자체는 stdout 출력이라 쓰기가 아니다. `git commit -m "$(cat <<'EOF' …)"` 커밋 메시지 heredoc + 메시지에 테스트 파일명 언급 조합이 [tdd]로 3연속 차단됐다(779c0f99 — 이미 Edit로 정상 편집·승인된 테스트 파일의 `git add`·커밋이 막힘).
   - 쓰기 연산과 대상 경로를 **명령 전체에서 따로** 매칭 — `perl -pi -e … src/foo.ts && npx jest foo.test.ts`처럼 쓰기 대상은 소스인데 뒤 세그먼트에 테스트 경로가 있으면 [tdd] 오차단(0101f9e8).
3. **advisory 스팸**: `setup_check.sh`의 permission_mode 경고가 `once:true` 선언에도 모든 Edit/Write마다 발화(3b8e61e1에서 31회+) — 신호 둔감화를 학습시키는 최악 유형(0017 맥락 6과 동류).

## 결정
1. **`cat <<`를 WRITE에서 제거한다.** heredoc이 파일 쓰기가 되는 경우는 `>` 리다이렉트가 동반될 때뿐이고, 그건 이미 WRITE의 `>`가 잡는다.
2. **WRITE 판정은 파이프라인 세그먼트 단위로.** 명령을 `&&`·`||`·`;`·`|`로 나눠, 쓰기 연산과 보호/생성물/테스트 경로가 **같은 세그먼트**에 있을 때만 deny한다. 따옴표 안 문자열 제거(2026-08-26 커밋 트레일러 수정)를 템플릿에도 승격해 세그먼트 판정 전에 적용한다 — 커밋 메시지 속 파일명 언급은 파일 인자가 아니다.
3. **advisory 경고는 세션당 1회.** `once:true`에 의존하지 않고 `.claude/state/` 세션 키 마커로 스크립트가 직접 보장한다.
4. **훅 버전 마커 + 드리프트 감지.** 템플릿 훅 1행에 `# cgamja-hooks v<N>`을 박고, `setup_check.sh`가 프로젝트 훅의 버전이 템플릿보다 낮으면 "훅이 구판(vN<vM) — /develop-setup 재실행" 경고를 1회 낸다. 1번(배포 경로 결함)의 재발 방지 — 고치는 건 여전히 develop-setup/사람.

## 전제
- 세그먼트 분할은 셸 파서가 아니라 근사다 — 정규식 내부의 `|` 등에서 과분할될 수 있으나, 과분할은 **deny를 줄이는 방향**(오탐→통과)으로만 작용한다. 누락(진짜 쓰기를 통과)이 2회 확인되면 해당 패턴만 명령 전체 매칭으로 복귀(0017 재검토 조건과 동일 원칙).
- 버전 마커는 수동 규율이다 — 템플릿을 고치면 v를 올리는 것을 잊으면 감지가 안 된다. 마커 갱신을 템플릿 수정 체크리스트(develop-setup SKILL.md)에 명시한다.

## 재검토 조건
- 세그먼트 판정 도입 후 진짜 쓰기 누락 2회 → 해당 검사만 전체 매칭 복귀.
- 버전 드리프트 경고가 떴는데 3세션 연속 방치 → develop-setup에 "시작 시 훅 diff 자동 제안" 승격.
- 오탐이 그래도 세션당 2건 이상 → 훅 범위 축소(7장 원 조건)로 이행.
