# 0024. 검출 사각지대의 체크리스트 승격 — 스펙 실패 의미론 3질문 + L1 React 관용구

- 상태: 제안
- 날짜: 2026-08-27
- 관련: 0004(TDD=게이트 — 시나리오가 곧 테스트 원천이라는 전제의 보완), 0012(렌즈), 0022(retro-fe — 본 ADR의 근거 공급원)
- 검증 근거: 2026-08-27 코드 감사(독립 렌즈 4개, 아티팩트 2f39f681)가 develop-fe 산출물(~/app, Tier-2 change 3개 통과분)에서 ⛔ 2건과 경쟁 창 3곳을 발견 — 전부 "테스트 98개 그린 + L1 리뷰 12회+ 통과" 상태로 존재했다. 루프 실행의 마찰이 아니라 **루프가 통과시킨 결함**이 근거다.

## 맥락
1. **시나리오 주도의 구조적 한계**: 테스트-먼저 루프는 스펙에 적힌 시나리오를 거의 완벽히 커버했다(76개 대비 실질 공백 3건). 그러나 응답 유실 재시도(→멱등 키 미재사용, 기록 중복 생성)·자원 만료(토큰·presigned URL·세션)·연타/동시 입력(stale closure 유실, 렌더 스냅샷 가드)은 **아무도 시나리오로 적지 않았고**, 그래서 테스트도 구현도 존재하지 않았다. 스키마 instruction은 empty/loading/error를 요구하지만 이들은 전부 "요청 1회의 실패"이지 "시간 축의 실패"가 아니다.
2. **L1 지시문의 공백**: reviewer-correctness는 "이벤트 핸들러 안 stale closure"를 이미 지시받지만, 실제 미검출 3건은 그보다 구체적인 React 관용구였다 — 스냅샷 기반 `setState(f(state))`(함수형 업데이터 미사용), 렌더 본문 중 ref 변이, 렌더 스냅샷 값(`isPending`)으로 만든 중복 실행 가드. 재실행(12회+)으로도 안 잡혔으니 비용이 아니라 지시문 문제다.

## 결정
1. **feature 스키마 specs instruction에 실패 의미론 3질문을 추가한다.** 상태 변이가 있는 기능이면 (a) 응답 유실 재시도 — 서버는 성공했는데 응답이 안 온 채 재시도하면? (b) 자원 수명 — 토큰·세션·서명 URL·캐시가 사용 중 만료되면? (c) 동시 입력 — 연타·진행 중 재제출·진행 중 이탈은? 해당하면 시나리오로 적고, **해당 없으면 "실패 의미론: 해당 없음"을 스펙에 명시**한다 — 공백이 아니라 결정이 되게.
2. **reviewer-correctness 검사 순서 2(로직)에 React 관용구 3항목을 명시한다**: 이전 상태 기반 setState의 함수형 업데이터 여부 / 렌더 본문의 ref 변이 / 렌더 스냅샷 값으로 만든 중복 실행·경쟁 가드(ref 아닌 것). 각각 실제 미검출 사례를 한 줄 예시로 박는다.
3. **전역 일관성은 이 ADR의 범위 밖.** diff 렌즈가 도메인 간 비대칭을 못 보는 문제(사각지대 B)는 상시 절차에 넣지 않는다 — retro 케이던스의 옵션 패스(retro-2026-08-27_audit 신규6, 채택 보류)로 남긴다. 티켓 루프 비용을 늘리지 않는 것이 원칙(0019).

## 전제
- 질문 3개는 스펙 분량을 늘릴 수 있다(시나리오 0~4개 증가 추정). "해당 없음" 한 줄 탈출구가 있으므로 Tier-2 스펙 작성 시간에 유의미한 증가는 없다고 본다 — 늘면 7장 "스펙 작성 > 구현 2번" 조건이 잡는다.
- 지시문 체크리스트는 길어질수록 희석된다 — L1에 추가하는 것은 3항목뿐이며, 다음 추가는 기존 항목의 검출 실적(lens-ledger)과 교환해야 한다.

## 재검토 조건
- 실패 의미론 질문이 2 change 연속 전부 "해당 없음" → 질문을 Tier-2 상태 변이 기능으로 한정.
- L1 신규 3항목이 3회 연속 지적 0 → 항목 축소(0012 §5와 동일 원리).
- 그럼에도 같은 부류 ⛔가 출하 후 감사에서 재발 → 체크리스트가 아니라 렌즈 분리(정확성 vs 동시성)를 검토.
