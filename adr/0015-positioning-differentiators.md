# 0015 — 차별점 재정의: 기계 강제·자기 테스트는 전제, 고유 가치는 증거 스택·선언 brownfield·비용 투명성

- 상태: 제안
- 날짜: 2026-08-24
- 관련: `docs/philosophy.md`(§1 개정은 사용자 몫), 0013(eval 층 — 상위 레포 방식 참고), 0014(선언 brownfield) · 지형표 원문 `docs/positioning.md`
- 검증: GitHub API star 실측 1회(2026-08-24, `docs/positioning.md` 표). 상위 레포 설치 실측 0회 — 표의 "구조" 열은 README 레벨이라고 명시함

## 맥락
2026-08-24 지형 실측: superpowers ⭐276.8k(자동 트리거 훅 + TDD 의무 + `superpowers-evals` + `tests/` 보유), anthropics/skills 171k, spec-kit 131k, OpenSpec 66k(우리 척추), BMAD 52k, compound-engineering 24.5k(우리 주변부). "규칙을 훅으로 강제한다 + 플러그인 자체를 테스트한다"는 생태계 1위도 갖춘 **표준 장비**다. 우리 문서(README·SKILL 설명·세션 보고)가 이를 차별점처럼 서술하면 과대 주장이고, 상위 레포와의 비교에서 바로 반박된다. 반면 조사 범위에서 유사물이 확인되지 않은 것: ① 프론트엔드 증거 스택(오라클 부재를 스크린샷·axe·SSIM·뷰포트·디자인 갭 루프로 메꾸는 P3~P6의 구체화), ② 선언 기반 brownfield(0014 — 스택을 읽고 맞추며 스캐폴드하지 않음; superpowers·spec-kit·BMAD는 전부 범용/greenfield 지향), ③ 런 단위 비용·실측 공개(`reports/` 원장, 티어 판정 시 예상 비용 고지).

## 결정
1. **차별점 서술은 세 가지로 고정**: ① 프론트 증거 스택 ② 선언 기반 brownfield ③ 비용·실측 투명성. README·SKILL 설명·세션 첫 보고에서 "훅 강제"·"자기 테스트"를 우위로 내세우지 않는다 — 전제(테이블 스테이크)로만 언급.
2. **`docs/positioning.md` 신설**: 지형표(레포 · star 실측일 · 겹치는 것 · 우리가 안 하는 것 · 빌려 쓰는 것) + 차별점 3개의 근거. 갱신 리추얼: 반기 1회 또는 "차별점이라 주장하는 기능이 상위 레포에 등장했다"는 신호를 봤을 때. star는 항상 API 실측, 블로그 집계 인용 금지(2026-08-24 블로그 수치가 실측과 3배 차이).
3. **빌려 쓰기 우선**: 상위 레포가 이미 검증한 조각은 재발명하지 않는다. 당장 하나 — 0013의 3층 행동 eval 러너를 설계할 때 `superpowers-evals`의 drill 방식을 설치·실측 후 참고(philosophy §5: 리서치만으로 결론 금지).
4. **philosophy.md §1 개정 제안**(사용자 승인 필요, §7): "무엇인가"에 한 줄 — *"generic 워크플로우 프레임워크(superpowers, spec-kit)와 겹치는 부분은 그들의 표준을 따르고, 이 플러그인은 프론트엔드 증거·디자인 원천·brownfield 선언에만 깊이를 만든다."*

## 기각한 대안
- "1위 따라잡기"(범용 스킬 확장, 스캐폴드 부활) — philosophy §2 위반, 2026-08-22에 이미 거부된 방향의 재탕.
- 지형 무시(비교 서술 자체를 안 함) — 사용자·기여자가 "superpowers 쓰면 되지 않나"에 답할 문서가 없으면 채택 대화가 매번 처음부터다.

## 재검토 조건
- 반기 조사에서 차별점 ①~③ 중 하나가 상위 레포에 등장 → 그 항목을 전제로 강등하고, 다음 차별점은 주장이 아니라 실측(런 리포트)에서 찾는다.
- 지형표를 근거로 기능을 추가하려는 유혹 2회 → 표에 "이 문서는 서술 근거이지 로드맵이 아니다" 경고를 승격.
- superpowers 설치 실측 후 "구조" 열 판단이 뒤집힌 항목 → 표 갱신 + 이 ADR 검증란에 기록.
