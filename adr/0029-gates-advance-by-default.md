# ADR 0029 — 게이트의 기본값을 정지에서 전진으로

- 상태: 제안 (2026-08-31)
- 관련: adr/0018(red 게이트 배치 승인), adr/0019(워크플로우 다이어트), adr/0003(디자인 갭 루프), reports/retro-2026-08-31_evening.md

## 문제

2026-08-31 `~/skill-test` 런(랜딩 4섹션 + 계약, 하루 8h23m, 커밋 61개)의 시간 분해:

| 구분 | 시간 | 비중 |
|---|---|---|
| **사람 응답·부재 대기** | **181분** | **36%** |
| 백그라운드 서브에이전트 대기 | 35분 | 7% |
| 모델 실작업 | 286분 | 57% |

대기 181분 중 **110분이 공백 두 개**다. 그리고 그 둘이 얻어낸 정보는 결정이 아니었다:

| 시각 | 길이 | 모델이 멈춘 이유 | 돌아온 답 |
|---|---|---|---|
| 18:10 | 49분 | "프리미엄 3개월 무료" 문구를 혜택 섹션과 폼 중 어디가 소유하나(3문항 AskUserQuestion) | 배치 위임 |
| 19:28 | 61분 | "디자인 세션이 먼저 필요합니다" — 데모 섹션 디자인 미확정이라 턴 종료 | **"ㄱㄱ 디자인 그냥 너가 알아서 만들어서 넣어놔"** |

두 번 다 사람이 되돌려준 것은 **위임**이었다. 하루의 22%를 정지 상태로 보내고 얻은 값이 "네가 정해라"다.

### 근인 — 문서의 의도와 도구의 성질이 어긋났다

`workflow.md` 2장 2번은 이미 올바른 것을 규정하고 있다:

> ⑤ **가정한 기본값 목록(반박만 받기)**

"반박만 받기"는 비차단을 뜻한다 — 가정을 알리고 진행하되 틀렸다면 되돌린다는 것. 그런데 구현 수단이 `AskUserQuestion`이다. 이 도구는 **답이 올 때까지 턴이 끝난다.** 반박을 받는 게 아니라 승인을 기다린다. 의도는 비차단인데 도구가 차단이라, 규정을 지킬수록 멈춘다.

두 번째 공백(61분)은 더 나쁘다 — 질문조차 아니었다. 모델이 "디자인 세션이 먼저 필요합니다"라며 턴을 끝냈다. `adr/0003`의 2-D 디자인 갭 루프는 **후보를 만들어 제시하는 절차**인데, 그 루프에 들어가는 대신 진입 허가를 기다렸다.

이건 질문 횟수 문제가 아니다. 그날 `AskUserQuestion`은 5회로 "최대 5개" 상한 안이었다. 문제는 **개수가 아니라 차단 여부**다.

## 결정

게이트의 기본값을 뒤집는다. **정지가 예외이고 전진이 기본이다.**

### 1. 정지 허용 목록 — 이것만 사람을 기다린다

| # | 사유 | 왜 사람만 답할 수 있나 |
|---|---|---|
| a | 되돌리기 어렵거나 밖으로 나가는 행동 — 배포·푸시·외부 전송·삭제 | 취소 비용이 대화 한 번보다 크다 |
| b | 계약 판정 **D** — 스펙에 없는 필드가 필요 | 계약은 다른 팀과의 약속이라 혼자 못 바꾼다 |
| c | 사용자만 아는 사실 — 비즈니스 규칙, 우선순위, 법적 제약, 실제 데이터 형태 | 코드에도 문서에도 없다 |
| d | red 게이트 세션당 1회 (adr/0018) | 테스트 변조 방지의 마지막 사람 확인 |
| e | 디자인 후보 **확정** | 취향은 사람 — 단 §3 참고 |

목록에 없으면 묻지 않는다.

### 2. 그 외는 "가정 전진" — 같은 턴에서 계속한다

멈추는 대신 세 줄을 남기고 작업을 이어간다.

```text
가정: <무엇을 정했나>
근거: <어디서 나왔나 — PRD §n, 기존 코드, 토큰, 관례>
되돌리는 비용: <틀렸을 때 무엇을 다시 해야 하나>
```

사용자는 나중에 이 줄만 보고 반박하면 된다. 반박이 오면 그때 고친다 — 이것이 원래 "반박만 받기"가 뜻한 것이다.

**정지 직전 자문 한 줄**: *"이 답이 '알아서 해'로 돌아올 확률이 높은가?"* 높으면 §1이 아니라 §2다. 2026-08-31의 두 공백은 둘 다 이 자문에서 걸러졌어야 했다.

### 3. 디자인 미확정은 정지 사유가 아니다

`adr/0003`의 2-D 루프를 **허가 없이 진입**한다. 순서는 후보 → 진행이지 허가 → 후보가 아니다:

1. 입력 수집(토큰·기존 컴포넌트·같은 플로우 Ready 화면)
2. 후보 2~3안 생성
3. 그중 하나를 **골라서 구현까지 진행**하고, 고른 이유와 나머지 안을 함께 보고
4. 사용자가 다른 안을 고르면 교체 — 섹션 하나 교체는 되돌리는 비용이 낮다

§1-e의 "확정"은 3번의 사후 확인이지 2번의 사전 허가가 아니다.

### 4. `AskUserQuestion`을 쓸 때의 형식

§1에 해당해 진짜로 물을 때는:
- 묶어서 **세션당 1회**(기존 규칙 유지)
- 각 질문에 **"답이 없으면 이것으로 진행합니다"** 기본값을 명시한다. 사용자가 자리를 비워도 무엇이 일어날지 알 수 있다
- 선택지는 4개 이하(하네스 제약), 첫 번째가 권장안

## 버린 대안

- **타임아웃 후 자동 진행** — `AskUserQuestion`에 타임아웃이 없다. 하네스가 주지 않는 기능을 절차로 흉내 낼 수 없다.
- **질문 총량 상한을 더 낮추기** — 그날 이미 상한 안(5회)이었다. 개수를 줄여도 남은 질문이 차단이면 같은 일이 벌어진다.
- **아무것도 묻지 않기** — §1의 다섯은 실제로 사람만 답할 수 있다. 특히 (a)는 되돌릴 수 없다.
- **가정을 커밋 메시지에만 남기기** — 사용자가 커밋을 읽는 시점은 이미 늦다. 대화에 남겨야 반박이 싸다.

## 비용

- **가정이 틀리면 되돌리는 작업이 생긴다.** 그래서 §2가 "되돌리는 비용" 줄을 강제한다 — 그 비용이 크다고 판단되면 §1로 올린다. 판단 기준은 "섹션 하나 다시 만들기"보다 싼가.
- 사용자가 보고를 안 읽으면 틀린 가정이 오래 살아남는다. 완화: 가정 세 줄은 **작업 시작 시점**에 내고, 세션 마무리 보고에 누적 목록을 다시 낸다.
- 자율성이 올라가는 만큼 사용자가 "내가 정한 게 아닌데" 하고 느낄 여지가 있다. 이건 §2 형식이 근거를 항상 밝히는 것으로만 완화된다.

## 강제

프롬프트 규칙이라 훅으로 막을 수 없다 — 이 ADR의 강제는 **회고 측정**이다.

`retro-fe`가 세션마다 다음 두 값을 집계하고 `reports/`에 남긴다:
- 사람 대기 시간이 세션에서 차지하는 비중
- 5분 이상 공백마다 직전 이벤트가 §1의 a~e 중 무엇이었나 — 어디에도 해당 안 되면 **이탈 1건**

## 재검토 조건

- 가정 전진이 실제로 되돌린 작업 **2회** → §1 정지 목록을 넓힌다.
- 사람 대기가 세션의 **25%를 넘는 런 2회** → 원인을 다시 분석한다(이 ADR이 겨눈 것이 원인이 아니었다는 뜻).
- 사용자가 "왜 안 물어봤냐"고 정정하는 일 **2회** → §2의 자문 기준이 느슨하다.
