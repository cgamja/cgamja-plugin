# 0022. retro-fe — 세션 트랜스크립트 감사 스킬: 마찰을 측정해 재검토 조건에 데이터를 공급한다, 자동 반영은 하지 않는다

- 상태: 제안
- 날짜: 2026-08-26
- 관련: 0016(렌즈 원장 — 리뷰 렌즈의 반영률 데이터), workflow.md 7장(재검토 조건), adr/README(같은 이탈 2회 → 개정 규약)
- 검증: 원형 런 1회(2026-08-26, 본 스킬 없이 수동 수행) — `~/app` 프로젝트의 develop-fe 세션 4개를 세션당 서브에이전트로 병렬 분석해 문제 20여 건을 훅/승인/커밋/시작 절차/증거 수단으로 분류, ADR 후보 6개(0017~0022)로 이어짐. 스킬화 후 재현 미검증

## 맥락
workflow.md 7장은 "10개 task마다 점검"하는 재검토 조건 13개를 갖지만, 조건 발동 여부를 판정할 **데이터를 모으는 절차가 없다**. "ask 프롬프트가 한 change에 10회 이상"(adr/0009 재검토 조건), "훅을 우회하는 습관", "같은 수정 2번 실패" 같은 조건은 전부 세션 트랜스크립트에 기록되어 있는데, 아무도 읽지 않으면 조건은 죽은 문장이다. 실제로 2026-08-25~26 세션 4개에서 훅 오탐·승인 피로·데드락이 반복됐지만 재검토는 사용자가 불편을 메모로 남긴 뒤에야 수동 분석으로 시작됐다.

"플러그인 자가 성장"(사용자 메모 2026-08-25)의 전체 자동화는 과하다 — 절차 변경은 ADR을 거쳐 사람이 결정한다는 레포 규약과 충돌한다. 그러나 **감사(측정·분류·제안)까지는 기계화할 수 있고**, 그 원형이 2026-08-26 수동 런으로 검증됐다: 세션당 분석 서브에이전트 병렬 → 마찰 신호 집계 → 스킬 설계/모델 행동/프로젝트 세팅 3분류 → 재검토 조건 대조 → ADR 후보.

## 결정
1. **`skills/retro-fe/` 신설.** 대상 프로젝트의 세션 트랜스크립트(최근 N개, 기본 4)를 읽어 마찰 신호를 집계하고, workflow.md 7장 재검토 조건과 대조해 발동된 조건을 표시하고, 개선 제안을 낸다.
2. **자동 반영 금지.** 산출물은 `reports/retro-<날짜>.md`(리포트)와 ADR **후보**(제목+한 줄 근거)까지다. workflow.md·훅·references를 이 스킬이 직접 고치지 않는다 — 반영은 사람이 ADR 새 번호로 결정한다(adr/README 규약). 렌즈 관련 신호는 `reports/lens-ledger.md`(adr/0016)에 **추가를 제안**하고 기록 자체는 리뷰 절차의 소관으로 남긴다.
3. **마찰 신호의 표준 목록**(스킬 본문 §신호): 훅 deny/ask 횟수와 사유 문자열, 사용자 인터럽트(`[Request interrupted by user]`)·정정·되물음, 같은 명령 재시도 루프, 티어·게이트 이탈(스킬 절차와 실제 행동의 diff), 도구 오류(`is_error`), 소요 시간·첫 가시 출력까지의 시간. 신호마다 "어느 재검토 조건의 입력인가"를 명시한다.
4. **세션당 분석은 `sonnet` 서브에이전트 병렬**(루브릭이 정해진 분류·집계 — `references/model-routing.md` §1), 세션 선택·집계·제안 판단은 본체. 트랜스크립트 원문은 본 컨텍스트에 덤프하지 않는다(수 MB — 서브에이전트가 파싱하고 증거 인용만 올린다).
5. **경계**: 대상 프로젝트의 트랜스크립트만 읽는다(`~/.claude/projects/<현재 프로젝트 슬러그>/`). 다른 프로젝트 세션·개인 대화는 열지 않는다. 리포트에는 판정에 필요한 최소 인용만 싣는다.

## 전제
- 트랜스크립트 포맷(JSONL, `type`/`message.content`/`toolUseResult`)은 Claude Code 내부 포맷이라 바뀔 수 있다 — 스킬 본문이 구조를 문서화하고, 파싱 실패 시 포맷 재확인부터 한다.
- 감사 비용은 세션 4개 기준 서브에이전트 4개(각 50~150k 토큰) — Tier-1 개발 한 건보다 비싸다. 10개 task마다 또는 사용자 요청 시에만 돈다(상시 아님).

## 재검토 조건
- 리포트의 제안이 2회 연속 ADR로 이어지지 않음(신호가 노이즈) → 신호 목록 §신호를 줄인다.
- 세션당 sonnet 분석이 같은 세션에서 사람 판정과 2회 어긋남 → 해당 신호만 본체 직접 분석으로.
- 트랜스크립트 포맷 변경으로 파싱이 깨짐 → 구조 문서 갱신 후 재검증.
