# 0021 — 증거 선언: 촬영 수단의 기본 동선 반전, 증거 매트릭스는 선언이 정한다

- 상태: 제안
- 날짜: 2026-08-26
- 관련: 0014(§슬롯 개정 — `evidence.*` 확장; 0014 본문은 그대로, 이 ADR이 슬롯을 추가한다), 0012(렌즈 — L4·L5의 증거 판정 입력), 0010
- 검증: 세션 회고 2026-08-26(대상 앱 레포의 Tier-2 2런, 2026-08-25~26 실측 트랜스크립트 분석). 반전된 동선 자체는 미검증 — 다음 UI change 1개에서 검증

## 맥락
`platform.profile: native` 프로젝트의 Tier-2 2런(2026-08-25~26)에서 증거 단계가 세션당 30~40분을 소모했고, 원인은 두 가지였다.

1. **기본 동선이 사용자 기대와 반대.** `evidence.screenshot`이 null이면 "촬영 수단을 사용자에게 요청"이 기본인데, 사용자는 곧바로 뒤집었다("너가 폰 틀어서 눌러보면서 찍어줘"). 에이전트 자체 촬영 절차가 어디에도 없어 클릭 자동화를 즉석 발명했고, 그 과정에서 같은 함정을 반복해서 밟았다 — 셸 호출마다 터미널이 포커스를 가져가 첫 클릭 유실, 안전영역 미보정 좌표, 클립보드 잔존값 입력, 재캡처 때 다른 기기가 부팅돼 좌표 전면 불일치, 캡처용 즉석 mock 서버가 선언된 경계 mock과 이중화(리뷰 렌즈가 드리프트 위험 지적).
2. **렌즈가 닫을 수 없는 blocker를 양산.** L5가 "다크 증거 0장"(디자인에 다크 팔레트 자체가 없음), "다른 플랫폼 증거 0장"(에뮬레이터 미설치)을 blocker로 판정했다. 코드로 닫을 수 없는 blocker는 "PR 알려진 한계"로 우회됐고, 이런 우회가 반복되면 게이트 신뢰가 깎인다(훅 오경보와 같은 부식 경로).

## 결정
1. **기본 동선 반전.** `evidence.screenshot`이 null이면 에이전트가 먼저 촬영 수단을 탐색해 직접 촬영을 시도한다 — 순서: 프로젝트 스크립트(`scripts/` 등 기존 수단) → 플랫폼 표준 도구(`references/evidence-capture.md` 검증된 구현 절) → 그래도 안 되면 사용자에게 요청. 성공한 수단은 선언(`evidence.screenshot`)에 기록해 다음 세션이 탐색을 건너뛰게 한다. "사용자에게 요청"은 최후 경로다.
2. **선언 키 확장** (`.claude/cgamja.json`, 0014 §슬롯에 추가):
   - `evidence.dark`(bool, 기본 true): 다크 모드 증거를 요구하는가. 디자인 원천에 다크 팔레트가 없으면 세팅이 false로 선언한다.
   - `evidence.platforms`(list | null): 증거를 낼 플랫폼/기기 목록. null이면 프로필 표의 기본 전부. 환경에 없는 것(예: 특정 OS 에뮬레이터 미설치)은 목록에서 빼고, 뺐다는 사실이 곧 선언이다.
3. **렌즈 조건화.** L4·L5는 `evidence.*` 선언 범위 안의 증거 부재만 blocker로 판정한다. 선언 밖(dark=false, platforms에 없는 플랫폼)의 부재는 blocker가 아니라 출력 맨 아래 **"선언된 한계"** 줄에 나열한다 — 숨기는 게 아니라 선언을 근거로 보고한다. 선언이 아예 없으면(키 부재) 기존 프로필 표 전부가 기준(보수적 기본).
4. **캡처 노하우는 reference로.** 즉석 발명을 멈추기 위해 `references/evidence-capture.md`를 만든다 — 앞부분은 스택 무관 원칙(수단 탐색 순서, 상태 재현은 선언된 경계 mock 재사용, 즉석 서버 금지, 캡처 전 대상 앱 포커스 고정, 기기 식별자 고정), 뒷부분은 "검증된 구현" 절(스택·날짜 라벨, 0014 §1-③).

## 전제
- 선언은 사실을 기록하지 게이트를 완화하는 스위치가 아니다 — `evidence.dark: false`는 "디자인에 다크가 없다"는 사실일 때만 쓴다. 귀찮아서 끄는 용도가 되면 재검토 조건에 걸린다.
- 촬영 수단 탐색은 세션당 1회다. 실패한 수단을 반복 시도하지 않는다.

## 재검토 조건
- 반전된 동선으로도 증거 단계가 20분을 넘는 세션 2회 → 수단 탐색을 세팅(develop-setup)의 프로브로 승격해 세팅 시점에 확정.
- `evidence.dark: false`인데 디자인에 다크 토큰이 발견됨 2회 → 선언 드리프트, 세팅 대조표에 다크 팔레트 검사 추가.
- "선언된 한계" 줄을 근거로 실제 결함(선언 밖 플랫폼에서 깨짐)이 출하 2회 → 3번 결정 철회, blocker로 복귀.

- `references/evidence-capture.md` 신설.
