# 0018. red 게이트 = 세션당 1회 승인 + 실패 원문 배치 확인 — 파일 편집마다 ask 폐지

- 상태: 제안 (0009의 ask 단위를 개정 — 0009는 대체됨(→0018))
- 날짜: 2026-08-26
- 관련: 0004(TDD = 게이트+변조 방지), 0009(ask 메커니즘 — 유지, 단위만 변경), 0017(보호 파일 ask·상태 디렉터리)
- 검증: 실사용 2세션(2026-08-25~26 Tier-2 change 2개). 0009가 스스로 적은 재검토 조건 — "ask 프롬프트가 한 change에 10회 이상 떠서 피로 → 'red 턴 시작' 1회 승인으로 바꾸는 메커니즘 검토" — 이 정확히 발동했다

## 맥락
0009는 "실패 테스트를 사람이 30초 읽고 승인하는 것이 스펙 리뷰"라며 테스트 파일 Edit마다 `ask`를 걸었다. 실사용에서 테스트 파일 Write/Edit는 한 change에 수십 번 일어났고(작성·분할·수정·재시도), 사용자 불만이 세 번 큐잉됐다: "그냥 너가 만들면안돼? 왜 계속 승인받아?", "물어보지 말고 계속 진행하라고", "테스트 수정하고 그런거 다 Yes로 해". 게이트는 전부-Yes 고무도장으로 퇴화했다 — 신호가 없는 승인은 게이트가 아니다.
같은 세션에서 승인 요청이 **실패 원문 없이 요약만** 제시돼 사용자가 두 번 되물은 사례도 있었다("왜 실패한 거야?", "정확히 어떤 요소들이 없어서 그러는데") — 설명이 thinking에만 있고 본문에 없었다. 게이트의 진짜 신호는 diff 프롬프트가 아니라 **red 실행의 실패 출력**이다.
한편 변조 방지(테스트를 초록으로 만들기 위한 수정 차단)는 편집 시점 ask가 아니라 **커밋 분리**가 실제로 잡았다: fix 커밋에 테스트 파일이 섞이자 commit-msg 훅이 차단한 실측(2026-08-25)이 있고, L3 렌즈(테스트 무결성)가 assertion 약화를 본다.

## 결정
1. **ask는 세션당 1회.** 이 세션의 **첫** 테스트 파일 Edit에만 `ask`가 뜬다. 사람이 승인하면(= Edit 성공) PostToolUse 훅(`red-mark.sh`)이 `.claude/state/red-approved-<session_id>` 마커를 쓰고, 같은 세션의 이후 테스트 편집은 묻지 않는다. `TDD_PHASE=red` 세션 키는 그대로(묻지 않음), 비대화형에서 첫 ask가 거부되면 테스트를 못 쓴다(0009와 동일 — 의도된 것).
2. **게이트의 신호는 실패 원문.** 각 red는 실행의 **실패 출력 원문(assertion별 핵심 줄)과 이유를 사용자에게 보이는 본문에 반드시 붙인 뒤** `test(scope):` 커밋한다. thinking·요약만으로는 게이트가 성립하지 않는다. 사람 리뷰 시점이 "편집마다 diff"에서 "red 배치 출력 + test 커밋"으로 이동하는 것.
3. **변조 방지의 주 담당은 커밋 분리 + L3 렌즈.** `feat` diff에 테스트 파일 금지(commit-msg 훅), 테스트 변경은 별도 `test()` 커밋, Bash 테스트 쓰기는 여전히 deny(diff가 안 보이는 경로, 0009 3항 유지), L3가 assertion 약화·mock 대상을 본다. 편집 시점 ask는 이 방어선의 중복이었다.
4. **사람 게이트 총량을 티어에 선언.** Tier-2 = 질문 1회(최대 5개) + red 게이트 1회(세션당) + 선택적 PR 전 확인. 그 외의 승인 요청은 절차 위반으로 본다.

## 전제
- 세션 마커는 에이전트도 쓸 수 있는 경로다. 방어는 0017 handoff와 같은 원리 — 은닉이 아니라 가시성(마커 생성은 PostToolUse 자동, 수동 생성은 트랜스크립트에 남는다) + 커밋 분리·L3가 실질 방어선.
- `.claude/state/`의 세션 마커는 커밋되지 않고(.gitignore) 쌓여도 무해하다.

## 재검토 조건
- 실패 원문 없이 test 커밋이 만들어진 change 2개 → 커밋 훅에 "test 커밋 메시지에 실패 요약 필수" 검사 추가 검토.
- 구현 턴의 테스트 몰래 수정이 L3·커밋 분리를 통과해 출하된 사례 1회 → 편집마다 ask로 복귀(0009 부활) 또는 marker를 task 단위로 축소.
- 사용자가 세션당 1회도 피로하다고 하면 → `TDD_PHASE=red` 기본 안내(사람이 세션을 red로 띄움)로 전환 검토.
